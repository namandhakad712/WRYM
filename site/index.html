Field Report · Dig Site I

A worm must eat every apple and reach its heart. Between them: one-way valves, crumbling bridges, frictionless ice, floor buttons, sealed gates, locks and keys, walnuts to push, spikes to respect — and a tight turn budget. Language models see only a text projection of the board and must reason turn by turn.

An exhaustive solver plays each level perfectly; that line is the par every model is measured against. A deterministic Checker re-plays every recorded run and signs it. Failure is expected — the information is in the failure.

Runs are executed locally by anyone, committed to this repository as JSON, and rendered here with zero computation. This page is a pure archive — no backend, no database, no JavaScript beyond the ledger you are reading.

Standings · Bradley-Terry MLE + bootstrap CI — the LMArena / Kaggle Game Arena estimator

Leaderboard

All-pairs battles on shared levels, fitted at once: a solved run beats an unsolved one; two solved runs are separated by efficiency (BFS-par ÷ model moves); two failures draw. Ratings are pooled Bradley-Terry MLE with bootstrap 95% confidence intervals (400 deterministic rounds) — order-free and uncertainty-quantified, superseding the old online Elo. Efficiency = BFS-par moves ÷ model moves. Progress = fine-grained BALROG-style partial credit (apples · goal · distance closure). Every model name links to its Artificial Analysis page — independent, third-party measurements (intelligence index, speed, price) by AA ↗. Head-to-head · shared-level records

Head-to-Head

Every pair of models that played the same level, all-pairs, one battle per shared level per pair. The matrix reads row-vs-column: wins–draws–losses. As in Kaggle Game Arena, the battles — not absolute scores — are the primary evidence.

Capability profiles · the SmartPlay lesson

What each model is actually good at

Every level declares which agent capabilities its geometry stresses (spatial · planning · dependencies · state-tracking · long-horizon · risk · precision), with measured intensity. A model's profile is its success rate on the levels carrying each tag, intensity-weighted — a diagnostic, not just a score. Tag derivation is deterministic: src/lib/wyrm/capabilities.ts.

Failure taxonomy · the information is in the failure

How models fail

Terminal-Bench-style error analysis, computed from per-step event logs: spike deaths (walked into teeth), budget exhaustion (ran out of turns), hard deaths, API aborts (rate limits, provider failures — reliability is part of the game), and invalid-action rate (grammar and rule violations per step).

The Ladder · thirty-one certified trials

Capability tags come from the level's own geometry. Full gallery with rendered boards on the Levels page.

Method · Plate II

How to read this archive

The benchmark pipeline
GENERATE → VALIDATE → SOLVE (BFS par) → SOLVE (LLM) → CHECK → ELO → COMMIT → PAGES

Validate — exhaustive BFS certifies solvability and computes the optimal move count (par) and the v3 difficulty index (seven dimensions, tier label).
Solve — the BFS solver plays perfectly (the par); each LLM plays from a frozen text projection only, with attempts, deaths and invalid actions recorded.
Check — a separate deterministic Checker replays the recorded actions on a fresh engine and signs the run CERTIFIED or INVALID. Models never grade themselves.
Commit — run JSON (every thought, every observation size, every retry) is committed to the repository; this site is regenerated from it. The leaderboard is a pure function of committed data.
